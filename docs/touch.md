# 触控适配（Android）

APK 里手指**不是**鼠标指针：框架层（pelya 的 SDL 1.2 Android 移植）把触摸翻译成鼠标事件，
游戏侧再补上触控语义。本文档写的是「手指能做什么」、相关设置在哪，以及哪些行为来自
本仓库的补丁。

## 1. 手势表

| 手势 | 效果 |
| --- | --- |
| 单指点按 | 左键点击（按钮、地图、窗口） |
| 单指按住不动约 1 秒 | 右键点击（长按出右键菜单） |
| 单指拖动 | 按住左键拖动：建造拖拽、拖滚动条 |
| 双指点按 | 右键点击 |
| 双指拖动 | 按住右键拖动 = **地图平移** |
| 双指触摸（建造拖拽中） | 取消当前建造动作，并重新选中上次用的工具 |
| 捏合 | 滚轮，默认 = 缩放 |
| 点输入框 | 弹出屏幕键盘（Android IME），直接打字；由 `gui.osk_activation` 控制，出厂配置是 `disabled`（不弹，需在游戏选项里打开）|

长按出右键是本仓库对框架的补丁（见 `packaging/README.md`）：出厂配置用的是
`AppNeedsTwoButtonMouse=y`，框架只会让**第二根手指**按下右键，所以双指拖动才能平移，
长按原本什么都不做。补丁保留双指方案，同时给单指长按也加上右键；移动、抬手、
第二根手指按下都会取消它，所以拖动建造和双指平移不受影响。

## 2. 游戏内设置（Options → Interface）

| 设置 | 作用 | 出厂值 |
| --- | --- | --- |
| `gui.build_confirmation` | 建造确认对话框：点一下不再直接建，先在手指下弹一个小 OK 按钮和费用预览 | 开（手机版出厂配置）|
| `gui.min_button` | 按钮最小尺寸（像素），按手指调整，与字号独立 | 0（关闭）|
| `gui.draw_mouse_cursor` | 画不画游戏自己的鼠标光标（触屏上手指已经指着位置）| 开 |
| `gui.windows_titlebars` | 画不画窗口标题栏 | 开 |
| `gui.windows_decorations` | 画不画窗口边框装饰 | 开 |
| Interface scale | 整体界面缩放 | 上游默认 |

出厂值放在 APK 安装的 `openttd.cfg` 里（打包树成员
`AndroidData/openttd-jgr-0.32.4.cfg`）。pelya 的启动器在升级时会重新下载这个文件，
所以**升级安装的新默认值会生效**，同时玩家自己的设置会被重置——这是框架本来的行为。
玩法/画面等其他项一律保持上游默认。

## 3. 启动器设置菜单（pelya 框架）

首次启动会进这个菜单；之后在启动画面（库加载完之后，`AndroidAppSettings.cfg` 的
`StartupMenuButtonTimeout` 指定的毫秒内）点屏幕上的大按钮也能进。里面和触控有关的项：

- **数据目录 / 屏幕尺寸**：`display size` 选 `small touchpad` 之类的触摸板模式（相对鼠标）
- **左键方式（leftclick）**：正常 / 靠近光标 / 双指 / 压力 / 超时 / 点按
- **右键方式（rightclick）**：双指 / 长按 / 按键 / 压力；选长按时长按也能出右键
- **长按时长**：右键超时时间，默认约 1 秒
- **触屏校准（calibration）**：屏幕坐标和手指位置有偏差时用
- **放大镜（magnifier）**：手指按住出现的放大区域，选小控件时用
- **屏幕按键 / 屏幕键盘**：额外的 LALT/RETURN/SPACE 等按键条

## 4. 本仓库的补丁落点

分两层：框架层在打包树里（改的是 pelya 的 SDL 启动器），游戏语义层在版本分支的游戏源码
里，每项一个带 `Android:` 前缀的独立 commit，方便将来 rebase 到上游新版本。

| 补丁 | 位置 | 状态 |
| --- | --- | --- |
| 长按出右键 | 打包树 `01-commandergenius.tar.xz`（`SDL_androidinput.c`）| 已有 |
| 出厂触控默认值（字体、`gui.build_confirmation = true`、`gui.osk_activation = disabled`）| 打包树 `AndroidData/openttd-jgr-0.32.4.cfg` | 已有（是否打开屏幕键盘待定）|
| 建造确认对话框 `gui.build_confirmation` | 版本分支游戏源码 | 已落地 |
| 最小按钮尺寸 `gui.min_button` | 同上 | 已落地 |
| 双指触摸取消当前动作并重选工具 | 同上（`#if defined(__ANDROID__)`）| 已落地 |
| `gui.draw_mouse_cursor` / `gui.windows_titlebars` / `gui.windows_decorations` | 同上 | 已落地 |
| 列表拖拽滚动、对话框拖到屏幕边缘关闭 | 同上 | 待做（阶段 B5）|
| 对话框横向重排（宽屏）| 同上 | 可选（阶段 C）|

这几个开关和最小按钮尺寸都是**设置项**（pelya 原方案就是如此）：默认值等于上游行为
（`min_button = 0`，其余三项为开），所以桌面构建不受影响，也不必在代码里到处加平台分支。
只有「双指取消」用了 `#if defined(__ANDROID__)`——桌面右键的语义（取消当前工具）不能改。

标题栏关掉之后，窗口并没有别的搬动方式（拖动标题栏是唯一的），「拖到屏幕边缘关闭」也还没
做：所以在这两项落地前，关掉标题栏会失去「搬窗」和「点 X 关窗」两个操作（用打开它的按钮
再点一次仍可关窗）。卷起的窗口在关闭标题栏时会被自动展开。

## 5. 验收注意

本仓库的 CI 只保证能编译出 APK，**触控行为必须真机验证**（本地没有 ADB，
模拟器是 x86_64 而 APK 只有 ARM）。改完触控相关代码后按第 1 节的手势表逐条走一遍。

本轮落地的功能，在真机上按这个顺序确认：

1. `gui.min_button` 调到 24 / 32：窗口按钮、下拉框、滚动条箭头、窗框上的关闭/缩放按钮都
   变大，字号不变；调回 0 恢复原样。
2. `gui.draw_mouse_cursor` 关掉：光标立刻消失（两个视频驱动都要试），选中建造工具时也只
   剩地图上的建造预览；打开后光标回来。
3. `gui.windows_titlebars` 关掉：窗口内容顶到窗口上沿；新闻窗口仍带标题栏；关之前卷起的
   窗口被展开；再打开时标题栏回来、窗口尺寸恢复。
4. `gui.windows_decorations` 关掉：窗口四边的花纹消失（界面缩放不是 100% 时本来就不画）。
